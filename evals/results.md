## Analysis

<!-- analysis:start -->
**Headline.** Adding the cross-encoder reranker is the only change that clearly matters. It lifts
recall@5 by 6 to 16 points for every first-stage retriever, and the paired bootstrap intervals of
the winner against every non-reranked config have lower bounds at or above zero. Among the top four reranked configs
(fixed/hybrid, heading/dense-lsa, heading/bm25, heading/hybrid) the differences are 0 to 4 points
with intervals spanning zero: on this gold set they are a statistical tie. `fixed/hybrid+rerank`
is listed first and is the API default, but "best" here means "one of four equivalent options".

**Why the reranker wins.** A bi-encoder or BM25 scores the question and a chunk independently;
the cross-encoder reads them together, so it can tell "the chunk that answers this" from "a chunk
that shares the vocabulary". Its ceiling is set by the first stage: it only reorders the top 20,
and candidate recall@20 is 86-98% depending on the retriever. That is also why hybrid is the
best first stage for reranking: fusing BM25 and MiniLM gives the highest candidate recall@20
(96% fixed, 98% heading), so the reranker has the most correct chunks to promote.

**Why BM25 is so strong and MiniLM so weak.** BM25 alone (77%) beats MiniLM alone (69-73%).
The questions use protocol identifiers (`server/discover`, `ttlMs`, `notifications/cancelled`)
and spec vocabulary, which exact term matching handles well and a small general-purpose sentence
embedder does not. The two fail on different questions (11 BM25-only hits, 7 MiniLM-only hits on
fixed chunks), which is the classic argument for hybrid retrieval, yet RRF fusion without a
reranker changes recall@5 by only -2 to +2 points versus BM25 here: rank fusion also imports MiniLM's mistakes.
Part of BM25's advantage is gold-set bias (questions written from the source text, see
`evals/GOLD.md`), so treat the BM25 vs dense gap as an upper bound.

**Chunking.** Fixed-size (757 chars on average) and heading-aware (827 chars) chunks are close in
size, so the comparison is fair, and neither wins consistently: heading-aware is better for
dense-only retrieval and reranked BM25/LSA, fixed is better for reranked hybrid. Heading-aware
chunks keep sections intact (better recall@10 in 7 of 8 pairings), fixed chunks with overlap more
often put the exact evidence sentence near the top of a short window. The differences are within
noise.

**Where the winner still fails.** Of 50 answerable questions, 6 miss at rank 5. Two (q19, q22)
retrieve passages from other pages that genuinely answer the question (for example
`learn/client-concepts` explains the input-required flow that q22 labels only in
`basic/patterns/index`). These are label misses, not retrieval misses: the gold set has one
labelled source per question, so recall is a lower bound. One (q03) needs two passages and finds
only one.

**Answer metrics (mock mode).** Citation accuracy is 34-44% because the mock answerer quotes the
two sentences with the most word overlap from the top 5 chunks, and the second sentence often
comes from a related but unlabelled chunk. Faithfulness is 100% by construction: the mock is
extractive, so the token-overlap heuristic can only confirm it copied text. Both numbers exist to
exercise the pipeline offline; they say nothing about live LLM answer quality.

**Refusals.** At threshold 0.35 the winner refuses 6 of 10 unanswerable questions and none of the
answerable ones (93.3% refusal accuracy). The confidence ranges of answerable (from 0.35) and
unanswerable (up to 0.47) questions overlap, so no threshold separates them perfectly: an
on-topic unanswerable question such as "Which Python web framework does the specification
require?" uses only corpus words. The threshold was chosen on this same set, so expect lower
accuracy on new questions.
